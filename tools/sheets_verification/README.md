# Sheets 저장소 검증 도구

이 패키지는 실제 `BigchatStore`를 전용 테스트 문서에서 실행하는 선택형 개발 도구다. 앱 코드와 일반 앱 테스트는 이 패키지를 가져오지 않는다. 운영 이미지도 `src/`만 포함하므로 도구와 검증 정책은 배포되지 않는다.

- `runner.py`: 명시한 커밋의 실제 저장소를 실행하고 결과·요청 해시를 기록한다.
- `boundary.py`: 지정한 테스트 문서와 사전에 계획한 새 탭 밖의 쓰기를 HTTP 전송 전에 차단한다.
- `tests/`: 문서·탭·metadata·참여자 열 범위를 벗어나는 요청과 CLI 진입점을 검증한다. 앱의 Sheets API 대역을 공유하지만 앱 테스트에서 도구를 참조하지 않는다.

## 외부 연결 없는 테스트

저장소 루트에서 `make test_sheets_verification`을 실행한다. `make ci`도 앱 테스트와 별도 pytest 실행으로 이 테스트를 수행한다. 루트 `conftest.py`가 양쪽 테스트에서 외부 소켓을 차단하며, CI는 실제 문서에 연결하지 않는다.

## 실제 테스트 문서에서 실행

헤더 없이 서로 다른 신청자 3~100개의 A:D 행이 있는 보존용 복사본 탭을 준비한다. 인증 JSON은 저장소 밖에 두고 서비스 계정에는 테스트 문서 편집 권한을 부여한다. 저장소 루트에서 실행한다.

```sh
uv run python -m tools.sheets_verification \
  --spreadsheet-id '<테스트 문서 ID>' \
  --source-sheet-id '<보존용 복사본 탭 ID>' \
  --credentials '/로컬/서비스계정.json' \
  --expected-head "$(git rev-parse HEAD)" \
  --output '/로컬/새로운-검증결과-폴더' \
  --run --browser
```

`--run`과 정확한 커밋 지정이 필요하다. 실행 전후에 앱·검증 도구·의존성 파일의 해시를 확인한다. 보존용 복사본은 읽기와 새 탭으로의 복제에만 사용한다. 쓰기는 `ANNA_TEST_`로 시작하는 이번 실행의 새 탭에만 허용하고, 삭제 검증도 새로 만든 삭제 전용 탭만 대상으로 한다.

생성 위치, 신청·재신청 순서, 리마인더 수신자 조회, 이름 충돌, 탭 삭제, 가득 찬 grid, 응답 유실, 전체·범위·필터 정렬을 검증한다. `--browser`를 지정하면 출력된 새 테스트 탭에서 정렬한 뒤 `ui_sheet`, `ui_range`, `ui_filter`를 입력해 검증을 이어간다. 값만 덮어쓰는 대조군에서는 연결 불일치를 검출해야 한다.

앱·Slack·예약 작업은 시작하지 않는다. 결과에는 원본 셀 값 대신 해시와 가상 사용자 ID를 남기며, 테스트 탭은 결과 확인을 위해 보존한다. `COMPLETE` 출력과 최종 결과의 모든 보호 검사가 성공했는지 확인해야 한다.

`--read-retry`를 추가하면 테스트 클라이언트에서 조회 응답에 한 번의 503 오류를 주입하고 실제 저장소가 재조회하여 복구하는지도 확인한다.
