# AUSG Notoriously Nerdy Assistant

![anna screenshot](.meta/docs/images/anna_screenshot.png)

## 멘션 명령어

안나를 멘션해서 쓴다. `help` 로 아래 목록을 슬랙에서도 볼 수 있다.

| 명령 | 하는 일 |
| --- | --- |
| `새로운 빅챗 <이름> yy-MM-DD HH:mm~HH:mm` | 빅챗 신청 시트를 만든다 |
| `빅챗 리마인더 테스트 @받을사람` | 리마인더 DM 을 지금 그 사람에게만 보내본다 |
| `빅챗 리마인더 지금 전원 발송` | 내일 빅챗 신청자 전원에게 리마인더 DM 을 지금 보낸다 |
| `새로운 이슈 <제목>` | 안나 레포(AUSG/anna-v2)에 깃허브 이슈를 만든다 |
| `shuffle` 또는 `섞어줘` | 같이 멘션된 사람들을 섞어준다 |
| `help` 또는 `도움` | 도움말 |
| 그 외 아무 말 | 질문으로 보고 답한다 (`q)` 를 붙이면 위 명령어보다 우선) |

이미 올린 메시지를 **수정해도 명령이 다시 실행되지는 않는다.**

멘션과 별개로, 지정 채널(현재 `fun-anna-house`)에 올라온 새 글에는 김수빈 말투로 자동 답글을 단다. 글에 `안나x` 를 넣으면 그 글에는 반응하지 않는다.

## 빅챗

### 1. 시트 만들기

```sh
@ANNA 새로운 빅챗 AI 밋업 26-08-20 19:00~21:00
# => "AI 밋업 26-08-20 19:00~21:00" 시트 생성
```

시트 이름이 곧 이벤트 정보다. `<이름> yy-MM-DD HH:mm~HH:mm` 형식이어야 하고, 실제 존재하는 날짜/시각에 종료가 시작보다 늦어야 한다. 이 형식이라야 캘린더 버튼과 리마인더가 동작한다.

메시지를 직접 치는 대신, 빅챗 소개글의 더보기 메뉴(`⋮`) > `새로운 빅챗 만들기` 로 폼(모달)을 띄워 만들 수도 있다. 스레드 안의 답글에서 실행해도 스레드 첫 글 기준으로 동작한다.

만들어진 시트는 [구글 스프레드시트](https://docs.google.com/spreadsheets/d/1FtKRO4gmlVg-Si0_CHt-tkpVd3LDTXdsoZ0u98MYd0k)에 추가되고, 그 링크가 달린 답글이 스레드에 올라간다. 시트 생성 시 모집글과 시트의 연결도 함께 저장하며, 참여·취소는 이 연결을 사용한다. 스레드에 임의의 시트 링크를 붙이는 것만으로 신청 대상을 바꿀 수 없다.

### 2. 참여 신청

모집글(스레드 첫 글)에 :gogo: 이모지를 달면 시트에 등록된다. 이모지를 떼면 등록이 취소된다. 일반 대화에서도 :gogo:를 자주 쓰므로, 모집글이 아닌 글이나 댓글에 단 :gogo:는 조용히 무시한다.

신청은 Slack 사용자 ID로 식별해 중복을 방지한다. 취소하면 해당 신청의 네 칸만 비우고 행은 지우지 않으므로 시트에 빈 행이 남는다. CSV로 내보내거나 인원을 셀 때는 빈 행을 빼야 한다. 배포 후 새로 만든 빅챗만 신청·취소를 지원하며, 배포 전에 만든 모집글에서는 이모지를 눌러도 아무 반응이 없다. 기존 시트의 데이터는 그대로 보존한다.

새 탭은 앞의 세 탭 다음에 생성한다. 탭이 세 개보다 적으면 마지막에 생성한다. 신규 신청은 처리 순서대로 아래에 추가하고, 취소 후 다시 신청하면 마지막에 추가한다. 이미 신청한 사람의 정보 갱신이나 중복 이벤트는 위치를 바꾸지 않는다.

같은 모집글에서 생성을 다시 요청하면 기존 신청 시트를 사용한다. 다른 모집글에서 같은 탭 이름을 사용하면 이름 충돌을 안내한다. 탭을 삭제한 뒤에는 생성·신청·취소 시 삭제 안내를 보내며, 자동으로 시트를 다시 만들지 않는다. Sheets에 접근하지 못해 모집글인지 확인할 수 없으면 스레드를 한 번 읽어, 봇이 그 모집글에 올린 시트 링크가 있을 때만 오류를 안내한다. 일반 글과 댓글의 :gogo:에는 장애 중에도 안내하지 않는다.

전체 시트 정렬, 신청 정보 네 열(A:D)의 범위 정렬, 기본 필터 정렬을 사용할 수 있다. 신청자 정보는 네 열을 함께 다뤄야 한다. 셀 값만 별도로 정렬해서 붙여넣거나 덮어쓰면 사용자 식별 정보와 값의 연결이 어긋날 수 있으므로 지원하지 않는다. 임의 가공이 필요하면 별도 조회 탭이나 내보낸 복사본을 사용한다.

- 등록되면 본인에게만 보이는 안내와 함께 **Google Calendar 추가 / .ics 다운로드** 버튼이 뜬다.
- 시트가 만들어지기 **전에** 이모지를 눌러둔 사람도 시트 생성 직후 자동으로 일괄 등록된다.

### 3. 전날 리마인더 DM

매일 저녁 6시(KST)에 다음 날 열리는 빅챗 시트를 찾아, 신청자 전원에게 DM 을 보낸다. 신청 시트의 이메일을 멤버 시트와 대조해 슬랙 계정을 찾는 방식이다.

6시까지 기다리지 않고 지금 돌리려면 위 표의 `빅챗 리마인더 …` 두 명령을 쓴다. 둘 다 "지금 기준 내일" 열리는 빅챗을 실제 발송과 똑같이 찾고, 다른 건 받는 사람뿐이다. 신청자 수와 슬랙 계정 매칭 결과를 함께 알려주므로 발송이 안 될 때 시트 이름 문제인지 이메일 매칭 문제인지 구분할 수 있다.

안전장치가 서로 반대 방향이다. 전원 발송은 되돌릴 수 없어서 `지금 전원 발송` 문구를 통째로 쳐야 실행되고, 테스트는 대상을 멘션하지 않으면 아무것도 보내지 않는다.

## 깃허브 이슈 만들기

슬랙에서 "이거 버그 같은데" 하고 흘러가버리는 이야기를, 그 자리에서 안나 레포의 이슈로 남긴다.

```sh
@ANNA 새로운 이슈 빅챗 리마인더가 두 번 와요
# => AUSG/anna-v2 에 이슈를 만들고, 그 링크를 스레드에 답글로 알려준다
```

`새로운 이슈` 외에 `이슈 만들어줘` / `이슈 등록해줘` / `이슈 파줘` 로도 부를 수 있다.

- **제목**: 명령 뒤의 첫 줄. 너무 길면 120자에서 자른다.
- **본문**: 둘째 줄부터 쓴 내용.
- **스레드 맥락**: 스레드 안에서 부르면 그 스레드 대화가 본문에 인용으로 함께 들어간다 (최근 3000자까지).
- **출처**: 본문 끝에 요청한 사람과 원문 permalink 가 붙어서, 이슈만 보고 슬랙 대화를 찾아갈 수 있다.

제목 없이 부르거나 실패했을 때의 안내는 요청한 사람에게만 보인다. 이슈가 만들어졌을 때만 스레드에 공개로 답글을 단다.

`GITHUB_TOKEN` 이 비어 있으면 이 명령은 동작하지 않고 그 사실만 알려준다. 토큰은 대상 레포에 대해 `Issues: Read and write` 권한만 있으면 되고(fine-grained PAT 기준), 대상 레포는 `GITHUB_REPO` 로 바꿀 수 있다 (기본값 `AUSG/anna-v2`).

## 개발환경 구축

Python 3.15 와 [uv](https://docs.astral.sh/uv/) 가 필요하다.

```sh
make setup_local_env
```

서브모듈을 받고 `uv sync` 로 의존성을 설치한 뒤 [prek](https://prek.j178.dev/) 커밋 훅(`prek.toml`)을 등록한다. 이후 명령어는 `uv run` 으로 실행한다. 포맷 검사(`ruff format`), 린트(`ruff check`), 타입 검사(`ty check`), 테스트(`pytest`)는 `make ci` 로 한 번에 돌린다.

로컬에서 켜고 끌 만한 환경변수:

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `BIGCHAT_REMINDER_ENABLED` | `true` | 리마인더 스케줄러. 로컬 인스턴스가 프로덕션과 같은 시크릿으로 뜨면 중복 발송되므로 끌 수 있다 |
| `ICS_TOKEN_SECRET` | 빈 값 | 비어 있으면 `.ics` 다운로드 버튼과 엔드포인트가 비활성화된다 |
| `GITHUB_TOKEN` | 빈 값 | 비어 있으면 이슈 생성 명령이 비활성화된다 |
| `GITHUB_REPO` | `AUSG/anna-v2` | 이슈를 만들 레포. 로컬 테스트 땐 개인 레포로 바꿔두면 안전하다 |
| `LOGLEVEL` | `DEBUG` | |

나머지 값(슬랙 토큰, GCP 키 등)은 [anna-v2-secret](https://github.com/AUSG/anna-v2-secret) 레포지토리에서 서브모듈로 받아온다.

### 코드 구성

```
src/
  anna.py              앱 생성과 의존성의 조립 및 수명 관리
  slack_events.py      Bolt 이벤트 등록, ACK와 명령 dispatch
  slack_router.py      외부 의존성 없는 문자열 명령 분류
  http_routes.py       HTTP 입력 검증과 응답
  jobs.py              예약 작업 실행과 관리자 오류 알림
  gunicorn_config.py   worker 초기화 후 예약 작업 시작
  features/<기능>/
    handlers/          슬랙 이벤트와 명령 처리
    models.py          기능별 값과 정책
    services/          처리 흐름과 조회
    presentation/      안내 문구와 답변 표현
  features/bigchat/calendar.py  빅챗 일정 해석과 캘린더 링크 및 파일 생성
  integrations/        외부 클라이언트와 시트 저장소
  shared/              오류 처리, 로딩 이모지, 스케줄러와 유틸리티
```

`anna.create_app()`은 앱을 생성하고 핸들러가 사용할 의존성을 연결한다. 예약 작업은 시작하지 않는다. `anna.start_jobs(app)`을 호출하면 활성화된 작업을 앱당 한 번씩 시작한다. Gunicorn에서는 `gunicorn_config.py`의 worker 초기화 훅에서 이 함수를 호출한다. `python src/anna.py`로 실행할 때도 앱을 만든 뒤 같은 함수를 호출한다. 예약 작업은 worker 한 개와 인스턴스 한 개로 운영하는 환경을 전제로 한다.

회원 조회와 QA 클라이언트는 처음 필요할 때 생성하고 같은 앱 안에서 공유한다. 이벤트 입력과 `say`, `ack`, 핸들러는 이벤트마다 새로 구성한다. 시트 클라이언트도 필요할 때만 생성하므로 도움말이나 인증에 실패한 캘린더 요청에는 Google 인증이 필요 없다. 캘린더 조회와 소개글 구성은 `features/bigchat/services/calendar.py`가 담당한다.

테스트는 `test/` 아래에 기능별로 배치한다. `test/test_anna.py`, `test/test_slack_events.py`, `test/test_slack_http.py`, `test/test_jobs.py`는 의존성의 수명, 이벤트 연결과 ACK 시점, HTTP 응답, 캘린더 다운로드, 예약 작업의 실패 처리를 검증한다. 테스트에서는 실제 외부 API 대신 테스트 대역을 사용한다.

빅챗 저장소는 모집글의 문서 단위 metadata와 탭 단위 binding을 함께 확인한다. 문서 단위 기록은 탭이 삭제돼도 남아 일반 메시지와 삭제된 빅챗을 구분한다. 모집글 metadata가 없는 경우에는 문서가 접근 가능한지도 확인해, 문서 자체의 404를 일반 메시지로 오인하지 않는다. 등록의 행 삽입·값·metadata는 하나의 batch로 저장하며, 재신청에도 고유 등록 기록을 넣어 응답 유실 후 같은 batch를 반복해도 중복 행이 생기지 않도록 한다. 이 저장 경로는 단일 인스턴스·단일 worker에서 동작하는 것을 전제로 한다.

Sheets 재시도는 `integrations/sheets_retry.py`의 Tenacity 정책으로 관리한다. 빅챗은 읽기 경계에, 회원 조회·시트 제목·탭 목록은 공개 읽기 메서드에만 데코레이터를 적용해 중첩 재시도를 없앴다. 통신 오류와 408·500·502·503·504는 1초·2초 간격, 429는 5초·10초·20초·30초 간격으로 재시도하며, 인증·권한·잘못된 요청·시트 부재와 프로그래밍 오류는 즉시 전파한다. 쓰기는 반드시 결과 확인을 먼저 거치며, 확인 실패를 쓰기 재시도로 해석하지 않는다.

참여자 metadata에는 마지막 Slack `event_ts`와 신청/취소 상태를 저장한다. 취소가 신청보다 먼저 처리되더라도 기록을 남기며, 오래된 이벤트와 생성 직후 자동 등록은 더 최신인 상태를 덮어쓸 수 없다. 상태 변경과 A:D 쓰기는 읽었던 metadata 버전을 필터로 사용한다. 새 형식의 리마인더는 같은 metadata와 활성 A:D 행에서 Slack 사용자 ID를 읽으므로 취소된 행의 E열 이후 메모를 신청 이메일로 해석하지 않는다. metadata binding이 없는 기존 시트는 종전 이메일 매칭을 유지한다.

저장소는 Slack 이벤트마다 새로 만들며, 같은 이벤트 안에서 이미 확인한 binding은 다시 읽지 않는다. Sheets 읽기 쿼터는 기본값이 사용자(서비스 계정)당 분당 60회라서, 읽기를 늘리는 변경은 신청이 몰릴 때 실패로 이어질 수 있다. 모집글 기록은 탭을 지워도 남으므로 계속 쌓인다. Sheets는 문서 단위 metadata를 key·value 합계 30,000자로 제한하고 기록 하나가 약 50자이므로, 빅챗이 약 600개에 이르기 전에 오래된 기록을 정리해야 한다.

## 실제 AUSG 슬랙과 로컬 안나를 연동해서 테스트하기

슬랙은 개발용 테스트 콜백을 따로 제공하지 않는다. 따라서 **실제** 이벤트를 로컬로 받아서 검증해야 한다. ~~super dog fooding~~ 이 작업 도중엔 슬랙의 안나가 졸게 되므로(작동하지 않으므로) 미리 공지해두는 게 좋다.

1. 안나 깨우기

```sh
make wakeup_anna
```

2. 로컬 포트를 개방한다. 외부에서 내 컴퓨터로 요청을 보낼 수 있도록 `tunnelmole`을 사용한다.

```sh
# 별도의 shell 에서 진행
make open_port
```

> 왜인지는 모르겠지만, ngrok 을 쓰면 슬랙의 검증 API 가 정상적으로 들어오지 않는다.

3. 슬랙 앱 설정의 Request URL 을 위 명령어가 뱉은 https 주소로 바꾼다.

> 💡 **바꾸기 전에 기존 값을 따로 저장해 둘 것.**

[Event Subscriptions](https://api.slack.com/apps/AR4RK9XGX/event-subscriptions) 의 `Request URL` 에 주소를 넣되, 그냥 URL 만 넣으면 안 되고 `/slack/events` 를 붙여야 한다[^1]. "Verified" 가 뜨면 하단 "Save Changes". 모달/버튼까지 테스트하려면 Interactivity & Shortcuts 의 `Request URL` 도 같은 주소로 바꾼다.

[^1]: 예를 들어 포워딩 URL 이 https://a.b.dev 라면, https://a.b.dev/slack/events 을 입력해야 한다.

4. 테스트가 끝나면 URL을 원래 값(`https://anna-v2-2023.fly.dev/slack/events`)으로 되돌린다.
